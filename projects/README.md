# Practice Projects

Each persona has one practice project, used throughout the course. The
exercises are written without reference to a specific project. They point to
**task slots** (like `P1.1`), and each project fills those slots with concrete
tasks.

To add or replace a project, create `projects/<persona>/PROJECT.md` that fills
in every slot below, plus any starter files the project needs. When the course
starts, the guide copies the starter files into `workspace/`.

## Project requirements

- Small enough to understand in 2 minutes.
- Has deliberate problems to fix: a bug, a data error, or a missing piece.
- Has a way to **verify** work: tests for engineers; a source of truth to check
  outputs against for business users.
- Needs nothing beyond the persona's baseline tools (see `docs/SETUP.md`).

## Task slots

| Slot | Module | What the project must provide |
|------|--------|-------------------------------|
| `P0.1` | 0 | A quick "explore and explain this project" task |
| `P0.2` | 0 | One safe action (run tests / generate a summary) and one destructive action to refuse (delete a key file) |
| `P1.1` | 1 | A defect whose symptom is easy to observe, for the vague-vs-specific prompt exercise |
| `P1.2` | 1 | A change with at least one real design choice, for the plan-first exercise |
| `P1.3` | 1 | A small new feature or deliverable that can be verified, for the one-prompt checkpoint |
| `P2.1` | 2 | Facts that belong in a memory file (how to run and check the project, conventions, known issues) |
| `P2.2` | 2 | A task large enough to hand off halfway |
| `P3.1` | 3 | A repeated workflow that should become a skill (release checklist / weekly report) |
| `P4.1` | 4 | An external system an MCP server could connect the project to |
| `P6.1` | 6 | A capstone task that uses every module |
